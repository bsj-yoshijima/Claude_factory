# デプロイ

**処理は `tools/deploy.sh` にある。手順をここに書き写して真似しないこと。**
スクリプトが唯一の真実で、あなたはそれを実行して結果を伝える係。

## 手順

### 1. まず事前チェックだけ走らせる（何も変更しない）

```bash
bash tools/deploy.sh
```

見るもの: ブランチ / 作業ツリー / `origin/main` との一致 / gcloud の認証 /
`.gcloudignore` / テスト / スキーマの世代。

### 2. 結果をユーザーに報告して、デプロイの可否を確認する

**チェックが落ちたら、そこで止まる。** 落ちた項目と、スクリプトが出した対処法を
そのまま伝える。勝手に直したり、チェックを回避して先に進めたりしない。

チェックが通ったら、**これから本番に出ることを伝えて確認を取る**。
このスキルは「意図したタイミングで出す」ための入口なので、確認を省かない。

### 3. 承認されたらデプロイする

```bash
bash tools/deploy.sh --deploy
```

スキーマの世代が上がっていて migrate が必要な場合は、**それが共有DBへの変更である
ことを伝えて別に承認を取ってから** `--migrate` を付ける。

```bash
bash tools/deploy.sh --deploy --migrate
```

### 4. 事後確認の結果を報告する

スクリプトがリビジョン・URL・`PUBLIC_URL` の維持・DB 接続・SSO の有効・
配信されているコードのハッシュ一致まで確認して出力する。
**問題があれば隠さずそのまま伝える**（デプロイ自体は完了しているので、
ロールバックが必要かの判断をユーザーに委ねる）。

## やってはいけないこと

- `gcloud run deploy` を自分で組み立てて実行する。**`--set-env-vars` を渡すと
  既存の環境変数が全置換され `PUBLIC_URL` が消える**（Cookie の Secure と OAuth の
  リダイレクトが壊れる）。スクリプトはこれを避けるため `--source` とリージョンしか渡さない
- チェックが落ちたのに `--deploy` を付ける
- 確認を取らずに `--migrate` を付ける
- `.env` の値を画面に出す

## 補足

ロールバックは Cloud Run のリビジョンを戻す。手順は [docs/deploy.md](../../../docs/deploy.md)。
スキーマを変えたデプロイを戻す場合、**DB は戻らない**点に注意する。
