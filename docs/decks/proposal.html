01

ターゲット

Claude Code を全社に広げたい組織と、そこで日々使う開発者。

使う側には「続ける理由」が要る。広げる側には「誰がどう使えているか」を知る手段が要る。Claude Factory はその2つを同じ仕組みで満たす。

使う人

毎日 Claude Code を叩く開発者

働いた分が製品になり、図鑑が埋まる。開くたびに何かが進んでいる。

広げる人

AI 活用を推進する側

誰が Skill / Agent を使いこなしているかが軸ごとに見える。会話の起点になる。

02

背景と課題

ツールを配ることはできる。使い続けてもらうことと、使えているかを測ることが難しい。

課題
  1. 導入しても定着しない「便利だから使って」で始まった活用は、忙しくなると最初に落ちる。使った分が何にも積み上がらないから、続ける理由が本人の中に残らない。
  2. 使い方が見えないSkill を書いている人、サブエージェントに任せている人、プロンプトだけでちまちま進めている人。差が出ているはずなのに、それを見る手段が標準には無い。
  3. 雑に測ると、測ったことで壊れる「活動量」を1つの数字にまとめて人を並べると、その数字を稼ぐ行動が強化される。下の実測がその危険をそのまま示している。
実測 — 単一スコアは「使いこなしている人」を上位にしない

10日ぶんのテレメトリで、WP（労働量）の構成比を測った。

Bash43.2%
Edit8.7%
Skill1.2%
Agent0.9%
評価したい Skill と Agent は、合計 2% しかない。 単一の合計値で並べると、Skill も Agent も使わず Bash を大量に叩く人が1位になる。 「上位の人に使い方を聞きに行く」という狙いと正反対の順位ができあがる。

つまり——続けさせる仕組みと測る仕組みは要る。ただし同じ数字を両方に使ってはいけない。

03

解決策 — 働いた量を、工場の生産に変える

Claude Code が出す実測値を WP（労働量） に換算し、そのWPで製品を作る。報酬をゲームの側に置くことで、続ける理由を本人の中に作る。

  • 働くと、工場が動く。busy のセッションは工場で手を動かし、idle のセッションは 💤 で眠る。別のディレクトリで claude を叩けば、次の瞬間に新しい仲間が出勤してくる。
  • WPが溜まると製品ができる。製造機は2〜5マス。1マス＝素材スロット1つで、1製品 = マス数 × 2,000WP。2マス機なら4,000WPで1個。
  • 組合せは教えない。入れた素材の集合でできる物が変わる。レシピに無ければ 🪨 謎のカタマリ。だから「当てにいく」動機が生まれる。
  • 図鑑を埋めるのがゴール。できた製品は図鑑に登録される。売れば 💰 になり、大きい製造機や32テーマの部屋・290種のプロップに変えられる。

原材料の組合せは見せて、できる物は隠す。84レシピを自分で埋めていく。

なぜゲームの形にするのか

管理ツールは、退屈だと開かれなくなって終わる。ドット絵の工場という「つい眺めたくなる」見た目は飾りではなく、可視化を習慣として続けさせるための設計。部屋テーマを32種そろえたのも、💰の使いどころ＝続ける理由を作るため。

設計の勘所
  • 重みはDBの表に置く。UPDATE するだけで全期間のWPが再集計される。バランス調整のために取り込み直す必要がない。
  • サーバが唯一の真実。💰・在庫・図鑑・製造判定はすべてサーバ側。クライアントの申告は信じない。工場のデータはブラウザに保存しない。
  • マスタはクライアントとサーバが同じものを import する。ジャンル・原材料・製品・レシピ・価格の定義は1箇所（game/data/*.mjs）で、値がズレようがない。

05

測る側の設計 — 2つの指標を分ける

02 の実測をふまえ、ゲーム用WPと業務スコアカードを完全に分けた。同じ数字を娯楽と評価に兼用しない。

ゲーム用WP

活動量。人と人の比較には使わない

製造を進めるための燃料。自分の工場が育つことだけに使い、順位付けの根拠にはしない。

業務スコアカード

多軸。単一の合計値を作らない

生カウントを軸ごとに並べる。1つに混ぜると必ず誤った行動を強化するため、合計は出さない。

壊れないための原則
  • 単一の合計値を作らない。1つに混ぜると、その数字を稼ぐ行動が必ず強化される。
  • スコアカードにサブエージェント係数をかけない。ゲーム用WPの ×0.5 は委譲を罰するので、推進の意図と正反対になる。
  • 効率には最低成果フィルタをかける。PR 1件かつ100行以上が対象。満たさない人はランク外（−）で、少量の成果で効率だけ高く出ることを防ぐ。
  • 効率と絶対量を必ず併記する。効率だけでは難易度の低い仕事が有利になる。
  • 順位は評価ではなく会話の起点。下位の人が上位の人に使い方を聞きに行くための表であって、査定の入力ではない。
