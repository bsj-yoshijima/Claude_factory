# 装飾品スプライトの発注（prop_<theme>_<slot>.png）

部屋・製造機と同じ「**殻を塗り替えさせる**」方式。殻が幾何を決め、Stitch にはテーマの意匠を任せる。

すぐ発注したいだけなら `docs/prop-prompts/README.md` へ。31テーマぶんの本文が生成済みで、
殻を添付して貼るだけで動く。このファイルは**なぜその形なのか**を残すためのもの。

---

## 0. 規格

唯一の出どころは `game/scene/iso.mjs` の `ISO`。1マスの接地菱形は **幅 55.65px / 高さ 27.83px**（厳密 2:1）。

| | 値 |
|---|---|
| 接地菱形の幅 | 1×1 = 55.65px / 1×2 = 83.5px / 2×2 = 111.3px（= マス数の和 × 27.83） |
| セルの幅 | 菱形の 1.15 倍 |
| セルの高さ | 中身の一番高い点 + 余白 0.18（比で決め打ちしない。物は菱形の奥に立つぶん上へ出る） |
| 高さの単位 | **1マスの幅 55.65px**。ブロックの菱形幅ではない（1×2 の物だけ1.5倍に化ける） |
| 枠と菱形 | シアン `#00E5FF`。焼き込みが色で見つけて消す |
| 背景 | マゼンタ `#FF00FF` |

### 守らせるもの / 任せるもの

| | |
|---|---|
| **絶対** | 足元の大きさ（菱形）・接地（枠の下辺に立つ）・カメラ（2:1）・枠を越えない |
| **手本** | 形と高さ。殻の絵は**プレースホルダ**で、テーマに合えば椅子が丸椅子でも座椅子でもよい |

足元が広がると盤面のマスに収まらない。ここだけは動かせない。それ以外は意匠の自由。

### 殻（`tools/preview/props.html` の「🧱 殻」で作る。Python は要らない）

| ファイル | 中身 |
|---|---|
| `docs/shells/prop-shell-sheet7-1519x1127.png` | 標準セット7種を1枚。chair/shelf/lamp/plant（1×1）+ table/sofa/rug（1×2） |
| `docs/shells/prop-shell-custom-1x1-372x499.png` | カスタム1体（1マス）。ダミーの四角が高さと接地面の手本 |
| `docs/shells/prop-shell-custom-1x2-423x567.png` | 同（細長い） |
| `docs/shells/prop-shell-custom-2x2-617x617.png` | 同（大きい） |

`.json` が対になっていて、焼き込みが並び順と接地線の位置（`gy`）を読む。

## 1. 手順

```
1. docs/prop-prompts/<theme>-sheet.txt の本文を Stitch に貼り、殻を1枚添付して生成
2. 出てきた画像を保存
3. node tools/assets/cut_prop_sheet.mjs <生成物.png> docs/shells/prop-shell-sheet7-1519x1127.json <prefix>
4. _contact-<prefix>.png を目で見る（数値だけで判断しない）
5. prop-fit-<prefix>.json を assets/props/prop-fit.json へ baked:1 付きで統合
```

名物・一点物は共通シートに入れず、`<theme>-custom-<形>.txt` で1体ずつ発注する。物ごとに
特徴も大きさも違うので、共通の型に押し込む意味がない。

## 2. 検証の記録（2026-08）

この方式に落ち着くまでに潰した分岐。同じ失敗を繰り返さないために残す。

| # | 試したこと | 結果 |
|---|---|---|
| 1 | 8体シート × 弱いプロンプト | **失敗**。接地菱形が1つも残らず、plant/lamp/名物は完全な正面図 |
| 2 | 1体 × 強いプロンプト（カメラ段落・上面指定を追加） | **成功**。稜線 0.53（2:1 なら 0.50） |
| 3 | 8体シート × 強いプロンプト | **成功**。稜線 0.50〜0.53、菱形の幅も一定 |
| 4 | 菱形を部屋の床と同じクリーム色にする | **失敗**。和紙の行灯・畳のラグと同色で、8体中4体が菱形を見失った |
| 5 | 菱形をシアンにする | 成功。ただし物が菱形を覆うと切り出しの基準にならない |
| 6 | セルをシアンの枠で囲む | **成功**。枠なら物に隠れても外周が残る。これが現行 |
| 7 | 部屋の絵をテーマの参照として2枚目に添える | **失敗**。カメラが崩れ、枠まで描き替えられた |
| 8 | 7 + 「1枚目を塗り替えろ、2枚目は参照のみ」を明示 | カメラは戻ったが**枠が塗りつぶしに化け、大きさが -20〜+12% ぶれた** |

**1 と 2 は体数とプロンプトを同時に変えていた**ので切り分けになっていなかった。3 を回して
初めて「原因は体数ではなくプロンプトの弱さ」と確定した。この手の思い込みが一番高くつく。

### 部屋の参照（7・8）を既定にしない理由

枠の幅が大きさの基準なので、枠が塗りつぶしに化けると**物に隠れた部分で外接矩形が縮み、
縮尺がぶれる**。テイストを寄せる利点はあるが、規格の安定と引き換えにはできない。
`docs/prop-prompts/<theme>-sheet-room.txt` として残してあるのは、生成モデルが変わったときに
再挑戦する価値があるため。

### 家具の語彙は正面図を呼ぶ

`chair` / `sofa` / `table` / `bench` / `counter` が正面図を誘発するのは
`docs/machine-sprite-prompt.md` にも先に記録がある。だから殻だけに頼らず、プロンプト側でも
「**上面が必ず見えること**」を具体名で書いて独立に担保する（座面の上・脚の上・鉢の縁…）。
正面図には上面が存在しないので、崩れたら一目で分かる。

## 3. 焼き込み（`tools/assets/cut_prop_sheet.mjs`）

```
1. シアンの連結成分を拾う
2. 「他の枠の外接矩形に収まっているものは枠ではない」で枠と菱形を分ける
3. 枠の幅 → 1マスの大きさ / 枠の下辺と gy → 接地線 / 枠の中心 → 横の中心
4. 枠の中身を切り出し、シアンとマゼンタを落として実寸へ縮小
5. 孤立した3px以下の点を除去
```

生成物は殻と同じ寸法では返らず並びも動くので、**殻の座標から推測してはいけない**
（ソファの位置から机が出た）。枠を見つけて切るので推測が入らない。

判定に使った数値の落とし穴:

- **「幅/菱形 = 1.00」は証拠にならない。** 見つけた菱形をマスの幅に合わせる処理なので、
  何を切り出しても必ず 1.00 になる。必ず `_contact-<prefix>.png` を目で見ること
- 「枠の外へ捨てた画素」は、枠が太いと帯が隣のセルへ届いて誤検知する（他の枠の内側は除外済み）
- シアンの判定は2段構え。**探すとき**は純粋なシアンだけ、**落とすとき**は青緑寄りを全部。
  線の縁の中間色が残ると切り抜きの縁にノイズが出る

### by が 1.0 を超えるのは正常（浮きではない）

`prop-fit.json` の `by`（接地点が画像の高さのどこか）は 1.0 を**超えてよい**。
足元がマスより小さい家具は、自分の接地菱形の手前角がマスの手前角より上に来るのが
正しいアイソメの見え方で、その差がそのまま `by > 1.0` として出る。

japan の実測: chair 1.015 / shelf 1.020 / lamp 1.015 / plant 1.010 /
table 1.033 / sofa 1.026 / rug 1.061。数字が大きいほど、その家具はマスを
埋め尽くさずコンパクトに描かれている、というだけ。

**これを「浮いている」と見て絵の最下点を接地点に使ってはいけない。**
小さい家具ほど手前へ押し出され、マスの中心からずれる。接地線は必ず枠から出す
（枠の下辺 ＝ マスの手前角）。一度この誤りで直しかけたので記録しておく。

### キャンバスの縁は枠の代わりにならない

カスタム（一点物）の殻から一度シアンの枠を外し、「1体だけなら画像の大きさが枠」とした。
**これは失敗だった。** japan の屏風を `384x533` で発注したら `848x1264` が返り、
縦横比が 0.720 → 0.671 と 7% ずれた。さらに接地菱形が縦に約10%伸び、
キャンバスの全幅いっぱいまで広がった（正しくは幅の86%）。

理由は単純で、**縁は絵ではない**から生成側が保てない。枠は描かれた線なので、
生成物の寸法が動いても線ごと一緒に動く。焼き込みは枠の幅を1マスとして読むので、
枠が絵の中に無いと大きさの基準が一つも残らない。

7点セットが寸法の変化に耐えていたのは、枠が絵として残っていたからで、
シートだからではない。**1体でも枠は描く。**

枠を戻したら寸法は保たれた（896x1200、縦横比 0.735 → 0.747 で 1.6% 差）。

### 次の失敗: 枠の下辺に接しない（縦に中央寄せされる）

枠を戻した屏風は幅は合った（枠に対する幅 0.94・はみ出し 0）が、**絵が枠の下辺から
浮いていた**。物の下端と接地線の間にマゼンタが残り、その隙間はマスの奥行きの 57%。
生成側が物を枠の中で縦に中央寄せし、下に床の余白を描いてしまう。

接地線は枠から出すので、この隙間はそのまま「マスの手前角より上に描かれた物」になり、
ゲームでは半マスぶん奥に浮く。

対策はプロンプト側。「下辺に立つ」だけでは足りず、**否定形で禁じる**必要があった:
「縦に中央寄せするな」「物の下端と下辺の間にマゼンタの隙間を作るな」
「余白は物の上に取れ、下ではない」「菱形は拡大・変形するな」。

焼き込みが `接地線との隙間` を出して 45% を超えたら ⚠ を付ける。実測の目安:

| | rug | table | sofa | chair | shelf | plant | lamp | 屏風(失敗) |
|---|---|---|---|---|---|---|---|---|
| 隙間 | 0% | 9% | 9% | 14% | 17% | 31% | 32% | **57%** |

### 生成側のキャンバスは3種類しかない → 殻の比をそれに合わせる

返ってくる画像は **1200x896 / 1024x1024 / 896x1200** の3つだけ（実測。どれも約1.07MP）。
頼んだ寸法は無視され、**いちばん近い比に丸めて描き直される**。

| 殻 | 頼んだ比 | 返った比 | ずれ |
|---|---|---|---|
| sheet7 1519x1127 | 1.348 | 1.339 | -0.6% |
| 1x2 417x567 | 0.735 | 0.747 | +1.5% |
| **2x2 557x617** | **0.903** | **1.000** | **+10.8%** |

2x2 だけ比が中途半端で、3:4 と 1:1 のあいだに取り残されて 1:1 へ丸められた。
結果、**高さの持ち分が1割減り、接地菱形が枠に対して 8% 太った**
（枠の内幅に対する菱形の幅 0.864 → 0.934）。dino の化石で発覚。

対策は殻の側。**キャンバスの比をこの3つのどれかに合わせる。** 広げるのは横だけで
（縦を詰めると背の高い名物が入らなくなる）、**枠はキャンバスの縁に引く**。

一度これを「枠はそのままにして外側にマゼンタの帯を足す」形で作ったが、枠の中に細い帯が
残る中途半端な絵になった。枠は縁まで広げてよい。枠の幅と足元の菱形の比が変わるだけで、
その比は殻の JSON に記録されるので縮尺は狂わない。**菱形そのものの大きさは変えていない**
ので、足元の規格は同じ。

| 形 | キャンバス＝枠 | 比 |
|---|---|---|
| 1x1 | 372x499 | 0.746 |
| 1x2 | 423x567 | 0.746 |
| 2x2 | 617x617 | 1.000 |

sheet7 は 0.6% しかずれていないので触っていない（1.348 → 1.339）。直すなら 1519x1134。
ただし29テーマの発注がこれから走るので、動いているものを 0.6% のために触らない判断。

**新しい殻を作るときは、必ずこの比のどれかに乗せること。** 部屋の背景 1376x768（1.792）と
製造機の殻 1024x1024 は最初から native な寸法なので影響を受けていない。どれも面積が
約1.05〜1.08MP で揃っているのが native の目印。

### カスタムは数字で位置を言う

部屋のプロンプトが「床は画像幅の65%・高さの59%」という言い方で効いているので、
1体だけのカスタムでも同じ書き方を入れた。言葉だけの「中央に・下辺に立つ」より、
**検算できる数字**の方が強い。7点シートは1枚に7つ並ぶので、この書き方は使えない。

| 形 | 接地点（下端からの位置） | 足元の幅 | 足元の高さ |
|---|---|---|---|
| 1x1 | 50.0% across / 97.8% down | 59.8% | 22.3% |
| 1x2 | 50.0% across / 97.0% down | 78.9% | 29.4% |
| 2x2 | 50.0% across / 96.4% down | 72.2% | 36.1% |

数字は殻の JSON（`sheet` と `gy`）と `CELL_W` から導いているので、殻を作り直せば
プロンプト側も自動で追従する。手で書き写さないこと。

### 枠を外して菱形だけにしないこと

「1体ずつなら枠は要らない。菱形を画像の縁に接触させればいい」は筋が通って見えるが、
**実測では逆の結果が出ている**。枠が無い殻（屏風・2026-08）では、生成側は菱形を
勝手に描き替えた: 縦横比 2.00 → **2.55**、幅はキャンバス一杯まで拡大。
枠を戻した回では菱形はほぼ保たれた。

理由は、菱形は**物に隠れる**こと。ラグのような平物や、底面の広い名物は菱形を覆い尽くす。
枠は物の外にあるので隠れない。菱形はカメラ（2:1）と足元の大きさを絵で教える役、
枠は切り出しの基準、と役割が分かれている。両方要る。

### 丸い物には別のルールが要る

幾何のルールが全部「箱」向けの言葉だった（`TWO vertical faces of any box` /
`the top of its base`）。onsen の露天風呂のような**丸い物**はどれにも当てはまらず、
モデルは円を描いて枠いっぱいに広げた。足元が枠幅いっぱい（正しくは 72.2%）になり、
リングの縦横比も 2:1 より潰れてカメラごと寝ていた。

丸い足元の指定を足した: **菱形に内接する楕円で、横は縦のちょうど2倍**。
真円や 2:1 より潰れた楕円は「カメラが真上へ寝た」印になる。

### さらに次: 菱形を巨大に描き替えて、その奥に物を置く

上の指定を入れた次の回、露天風呂は**菱形そのものを 1:1 の巨大な四角(45度回転)に
描き替え**、キャンバス全面を床にして、その奥に風呂を浮かせた。足元の幅は
72% とほぼ合っていたのに、接地点が 74% 付近（正しくは 96.4%）だった。

**「物の下にマゼンタの隙間を作るな」という禁止は、隙間を自前の床で埋められると効かない。**
屏風のときはこの書き方で直ったが、あれは隙間がマゼンタのままだったから。

書き方を「殻の話」から**「物の話」**へ変えた:

- 接地点は**物自身の最下点**。その下には床も水も石も影も何も無く、マゼンタだけ
- 足元の大きさは「菱形の大きさ」ではなく**物が床に触れている部分**の大きさ
- **画像の四隅はマゼンタのまま**。埋まっていたら自前の床を描いた証拠
- 菱形は殻に既にある。**描く対象ではない**。大きく描いてその奥に立たせるのが最頻の失敗

### 印のシアンと「絵に使った水色」がぶつかる

onsen の露天風呂で**湯が丸ごと消えた**。原因は、シアンを**色だけで落としていた**こと。

| | rgb | 枠を探す判定 | 落とす判定(旧) |
|---|---|---|---|
| 印のシアン | 0,229,255 | ○ | ○ |
| 湯 | 175,241,231 | **○**(差1ポイント) | ○ |
| 湯(淡い所) | 207,238,240 | × | **○** ← 消えた |

ice・undersea・空色の物すべてで同じことが起きる。2つ直した。

1. **印の判定を「#00E5FF からの距離」1本にした。** しきい値を積み上げるより壊れにくい。

   | | rgb | #00E5FF からの距離 |
   |---|---|---|
   | 枠の芯 | 7,229,255 / 20,224,248 | **7 / 22** |
   | 影の湯 | 117,201,203 | 131 |
   | 明るい湯 | 175,241,231 | 182 |

   しきい値は 70。旧判定（緑と青が赤より55以上高い）では、明るい湯が **1ポイント差**
   （231-175=56）で印と判定され、影の湯も同じ理由で奥側が欠けた。
2. **落とすのは「印の画素」と「その数px以内にある青緑寄りの画素」だけ**にした。
   印から離れた水色は残る。線の縁の中間色は膨張ぶんで消える。

他に2つ試して駄目だった:

- **膨張だけ（色を見ない）** … 線に触れた絵の下端が削れて物が数%浮いた（japan 14%→22%）
- **つながりで塗る（印から連結する青緑を全部）** … もっと悪い。湯が1点でも菱形に
  触れていれば全部つながって消える。露天風呂の湯が丸ごと落ちた

**色（距離）と近さの両方**で判定するのが正解だった。

japan / dino / onsen の7点セットは、この変更の前後で**数値が完全に一致**することを確認済み。

### 一点物の救済に `--scale` と `--pad`

生成物が規格から外れたとき、作り直す代わりに焼き込み側で直す手。使うと fit に
`scale` / `pad` が残るので、後から効いているのが分かる。

| | 意味 |
|---|---|
| `--scale 0.4` | 絵を縮める。枠に対して大きすぎるとき |
| `--pad 8` | 絵の下に透明の余白を 8px 足し、PNGの下端を接地線にする（`by=1`）。上にも同じ量を足す |

`--pad` の下の余白がそのまま「マスの手前角からどれだけ奥に置くか」になる。
**上の余白は盤面の見え方を変えない**（接地点は比率 `by` で持つので、高さと `by` が同じ
割合で増える）。一覧（レイアウト編集のパレット・ショップ）で PNG をそのまま並べたとき、
下だけ余白があると絵が枠の上寄りに見えるので、体裁のために足している。

**共通7種には使わないこと。** そこは殻とプロンプトで揃うのが正で、係数で誤魔化すと
規格そのものが崩れる。名物の一点物だけの逃げ道。

#### 前後の位置合わせで2回まわり道した

露天風呂が前後にずれる問題で、置き方の指定を3回変えている。記録しておく。

| | やったこと | 結果 |
|---|---|---|
| `--sit` | 絵の最下点を接地線へ | **失敗**。マスより小さい物がマスの前半分に寄る |
| `--center` | 外接矩形の中心をマスの中心へ | 計算は合うが、見た目はまだ手前だった |
| `--pad N` | 下に N px の余白を足す | 数字と見え方が直結する。これが現行 |

`--sit` が捨てていたのは、この文書の「by が 1.0 を超えるのは正常」そのもの。
マスを埋め尽くさない物ほど自分の手前角がマスの手前角より上に来るのが正しく、
最下点を手前角に合わせると前へ出る。**自動で中心を出そうとせず、余白の px を
直に指定して目で見て決める**のが、結局いちばん早くて確実だった。

### 「枠に対する幅」は殻の取り方で変わる → 「絵の幅/マス」も見る

枠を広げたぶん `枠に対する幅` は小さく出る。盤面の寸法そのもので見たいときは、
焼き込みが一緒に出す `絵の幅/マス`（絵の幅 ÷ 接地菱形の幅）の方。

ただし**これは足元の大きさではない**。張り出しも数えるので、尻尾のある化石や
葉の広がる植物は 1.1 前後になるのが正常。実測:

| | lamp | shelf | chair | table | sofa | plant | rug | 化石(尻尾つき) |
|---|---|---|---|---|---|---|---|---|
| 絵の幅/マス | 0.61 | 0.72 | 0.74 | 0.91 | 0.92 | 0.93 | 0.96 | 1.13 |

閾値は 1.20 に置いた。**一度 1.05 にして正常な化石を弾いた**ので下げないこと。
足元が本当に大きいかは、結局コンタクトシートと部屋で目で見るしかない。

なおプロンプトには別の誤りもあった。「枠の幅＝1マス」と書いていたが、これが正しいのは
1x1 だけで、1x2 は1.5マス・2x2 は2マスぶんの幅がある。「幅から縮尺を出すので比を保て」
という書き方に直した。

## 4. ゲーム側

### `prop-fit.json` のキー

1体につき1エントリ。**新規格と旧規格でキーが違う**（下表の「規格」列）。
座標はすべて**その画像に対する比**で、px 単位の値ではない。

| キー | 規格 | 意味 |
|---|---|---|
| `cx` | 両方 | 接地点の中心 x（画像幅に対する比 0〜1）。新規格は枠の中心、旧規格は実測した足元の中心 |
| `by` | 両方 | 接地線の y（画像高さに対する比）。**1.0 を超えてよい**（→ 3節） |
| `px` | 両方 | `[画像の幅, 高さ]` のピクセル実寸。**描画には使わない**。`tools/preview/props.html` の表示と、絵を差し替えたときの差分確認のための記録 |
| `baked` | 新 | `1` なら新規格。等倍・接地点合わせで描く。統合時に手で付ける |
| `shape` | 新 | 焼き込み時に確定した占有 `[列,行]`。**これが無いと `FURN_SPAN` に落ちて半マスずれる** |
| `scale` `pad` `bleed` `flip` `markTol` `markZone` | 新 | 焼き込み時に既定から外したオプションの控え。同じ絵を焼き直すときに同じ結果を出すためのもので、ゲームは読まない（`pad` を使うと `by` は 1 固定になる） |
| `bw` | 旧 | 足元の幅（比）。新規格の `PROP_FIT.foot` に合わせる基準 |
| `w` `h` `left` `right` | 旧 | 不透明部分の外接矩形（比）。上限クランプに使う |
| `flags` | 旧 | 実測時の注記（`narrowBase` / `skew` / `wide` / `edge` / `manual`）|

新規格は `tools/assets/cut_prop_sheet.mjs` が枠から機械的に出す。**手で詰める調整値ではない**ので、
盤面でずれたときに `cx`/`by` をいじるのは筋が悪い（殻か焼き込みを疑う）。
旧規格は `tools/assets/measure_props.mjs` が絵から推測した値。

### 描画

`assets/props/prop-fit.json` の `baked:1` が付いた個体だけ新規格で描く。

```js
const [n,m]=this.propBlock(e), b=blockIso(c,r,n,m);
img.setOrigin(f.cx, f.by).setPosition((b.back.x+b.front.x)/2, b.front.y).setScale(1);
```

倍率の計算も上限のクランプも無い。焼き込みの時点で1マスに合わせてあるため。

- **形は fit が持つ**（`shape`）。コマ数の表 `FURN_SPAN` は旧290体むけで、lamp が 2コマになっている。
  表に従うと 1×2 ブロックの中心へ置かれて半マスずれる
- **横は菱形の中心x、縦は手前角のy**。1×2 では手前角が中心から半マス（14px）ずれる
- **複数マス占有と回転は新規格だけ**。旧290体に広げると保存済みレイアウトが復元できなくなる
- 回転は絵の左右反転（アイソメでは水平反転が90度回転に相当。製造機と同じ手）

旧290体は `tools/assets/measure_props.mjs` が絵から推測した足元で描く。こちらは規格が無い
時代の資産なので、推測で救っている（→ `docs/stitch-prompts.md` の2節）。

## 5. よくある失敗

- **数値だけで合否を決める** … 一番高くついた。必ず絵を見る
- 変数を2つ同時に変えて切り分けたつもりになる … 1〜3 で実際にやった
- 1枚に複数体を詰めるのが原因だと決めつける … 原因はプロンプトの弱さだった
- カメラの担保を殻だけに頼る … 絵が無視されたときに受け皿が無い
- 菱形や枠を「絵に使う色」にする … 家具と同色になって焼き込みが見失う
- **接地面の上限を「目標」と読まれる** … tokyo の自販機(1×1カスタム)がこれ。枠・比・カメラ・
  四隅は全部守られていたのに、接地面が画像幅の約80%(規定59.8%)まで太り、最下点も66%へずれて
  菱形を飲み込んだ。菱形が絵の下に隠れたら接地面が大きすぎる合図。`-orange` 版では
  「59.8%は上限であって目標ではない」「終わったとき菱形の縁が四方に見えていること」
  「自販機は幅の2倍の高さの細いキャビネット」を足した
- **「菱形が見えていること」と書く** … 上の対策が裏目に出た。生成側は物を縮めるのではなく
  **菱形を画像いっぱいまで広げて**その条件を満たし、キャンバスも 1024x1024 の正方へ
  丸めて割り付けごと描き直した。見た目の条件で頼むと逃げ道の方を選ばれる。
  菱形は「59.8% / 22.3% / 手前角 50.0%,97.8%」の絶対値で縛り、
  「入らないなら物を縮めるのが唯一の正解」と書くこと。
  なお**菱形の大きさは焼き込みには効かない**（縮尺は枠の幅、接地線は枠の下辺と gy）。
  菱形が育っただけの絵は、まず切り出して `_contact-*.png` を見るほうが早い。
  この2件を受けて、カスタム3種すべての本文に「上限であって目標ではない」「仕上がりでも
  菱形は N% のまま」「キャンバスの比を変えるな」を入れた（`prop_prompt.mjs` の
  `buildCustom`。数字は殻の JSON から自動で入る）
- em dash（—）を入れる … Stitch API が `Request contains an invalid argument.` を返す
