01

ターゲット

Claude ユーザー — とくに Claude Code を毎日使い、プロジェクトやタスクごとに複数のセッションを同時に走らせている開発者とチーム。

「1ターミナル1作業」の時代はもう終わりました。何体ものClaudeを並行で走らせるのが当たり前——そんな働き方をしている人のためのツールです。

02

背景と課題

エージェントの数は増える一方。なのに、それを見渡す手段だけがありません。

背景 — なぜ同時に何体も動くのか
  • 使い方が「並行」になった。 ひとつ終わるのを待ってから次へ、ではなく、プロジェクトごと・タスクごとにセッションを分けて同時に走らせるのが普通のスタイルに。
  • 見えないところでも働いている。 サブエージェントやバックグラウンドタスクが増え、「自分が画面で見ていないClaude」が裏で何体も動いている。
  • 気づけば二桁。 1人で10〜20セッションを抱えるのはもう珍しくありません。実際、この企画書を書いていた環境でも 15体 が起動していました。
課題 — なぜ管理が必要か
  1. 総数が見えない「あれ、これさっきも起動したっけ？」——二重起動、起動しっぱなし、存在ごと忘れられたセッション。今いくつ動いているか、正確に答えられる人はいない。
  2. 状態が見えない戻ってみたら、10分前から確認待ちで止まっていた——。どれが作業中(busy)でどれが応答待ち(idle)か分からず、待たせた時間がまるごとムダになる。
  3. 放置＝コスト動いている限り、トークンもAPIもマシン資源も消費し続ける。「使っていないのに動いている」セッションが、静かに積み重なっていく。
  4. コンテキストスイッチ地獄ターミナルを何枚も行き来して「このタブ、何のタスクだったっけ？」。切り替えるたびに思い出すコストを払っている。
  5. 俯瞰する手段がそもそもない自分やチームのClaudeが今どう動いているかを一望する仕組みは、標準には存在しない。結局ぜんぶ、記憶で管理するしかなかった。

つまり——並行稼働は日常になったのに、それを一望する“計器盤”だけがまだ無い。ここに空白があります。

03

解決策 — Claude Factory

いま動いているセッションのすべてを、1画面に。開いて3秒で全体がつかめるダッシュボードです。

  • 数字を探さなくていい。 稼働中／待機中／合計を常にリアルタイム表示。「今いくつ動いてる？」への答えが、視界に入った瞬間に出ている。
  • 状態は“読む”のではなく“見る”。 各エージェントは工場で働くClaude。busyなら手を動かし、idleなら zzz と眠る。眠っている子が目に入れば「あ、返事を待たせてるな」と気づける。プロセス一覧を読み解く必要はもうない。
  • だから毎日開ける。 管理ツールは、退屈だと開かれなくなって終わる。ドット絵の工場という“つい眺めたくなる”見た目は遊びではなく、可視化を習慣として続けさせるための設計です。
