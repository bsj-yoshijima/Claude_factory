# タスク: 原材料・製品のアイコンを絵文字からドット絵に置き換える

別セッションで進めるための指示書。**このファイルを最初に読んでから着手すること。**

## ゴール

いま原材料と製品は OS の絵文字（🥛 🌾 🥣 …）で表示している。盤面と部屋の背景はドット絵なのに
アイコンだけフォント任せで、環境によって形も色も変わる。**部屋背景と同じ絵のタッチのドット絵**に
置き換えたい。

先例がある。メニューのアイコンは同じ理由で絵文字から置き換えた（`tools/assets/make_menu_icons.mjs`
の冒頭コメントに経緯がある）。あちらは手で描いたが、今回は数が多いので Stitch で生成する。

## 対象と数

| 種別 | 定義 | 数 |
|---|---|---|
| 原材料 | `game/data/craft.mjs` の `MATS` | 32 |
| 製品 | `game/data/craft.mjs` の `PRODS` | 113 |
| ジャンル | 同 `GENRES`（🍳食品 / ⚙️機械 / 🧺生活品） | 3 |

**合計148枚。多い。** いきなり全部作らないこと。まず原材料32枚で型を固めて、
実機で見た目を確認してから製品に進む。製品はジャンル単位（食品→機械→生活品）で刻む。

`id` と `e`(絵文字) と `n`(表示名) は craft.mjs にある。**id をファイル名に使うこと**。

## どこに出るアイコンか（サイズの根拠）

1. **盤面の製造機の投入口** — `game/scene/machine-art.mjs` の 208〜222 行。
   いまは絵文字ではなく `matArt(id)` が返す**色の楕円/四角**だけを描いている（絵文字は出していない）。
   ここにドット絵を出すなら描画コードの変更が必要。1マスは 27.8×13.9px なので、載せられるのは
   16×16 程度。
2. **製造機の設定ダイアログの原材料パレット** — `game/ui/craft-dialog.mjs:33`。`x.e` を直に出している。
3. **レシピ一覧** — `game/ui/recipes.mjs:13,15,17`。原材料チップと製品アイコン。未発見はシルエット表示（`.sil`）。
4. **図鑑** — `game/ui/collection.mjs`。
5. **ジャンル見出し** — 上記各所の `g.e`。

文字サイズは 12〜16px の中に並ぶので、**16×16 を原寸**が基本。ショップの行のように枠が大きい所は
`uic()` の `lg` と同じ考え方で 2倍(32px)に拡大して使う。
→ **16×16 のドット絵で作る。** 32×32 で描いて 16px で出すのは禁止（1ドット飛びに間引かれて濁る）。
　 大きく見せたいときは整数倍の拡大だけ（`image-rendering:pixelated`）。

## 作り方の方針（既存の流儀に合わせる）

### 生成
- Stitch で**シート生成**（1枚に複数個）→ マゼンタ抜き → 個別スライス。
  プロップと同じ流儀。プロンプトの型は `docs/stitch-prompts.md` の
  「2. オブジェクト(小物)テンプレート」がそのまま参考になる（マゼンタ背景・4個を横1列）。
- 部屋背景と絵のタッチを揃えるため、プロンプトには背景と同じ**画風の固定句**を入れる:
  `lo-fi 8-bit Famicom pixel art, chunky pixels, thick clean black outlines, flat colours, high contrast`
- ただし背景はアイソメだが、**アイコンは正面向きの方が小さくても読める**。
  アイソメにするか正面にするかは最初の32枚で決めて、以降ぶれさせないこと。
- **16×16 は非常に小さい。** Stitch には大きく描かせて縮小する。縮小は必ず整数分の1か
  LANCZOS で（`tools/assets/shrink_hats.py` が同じことをしている。あれは長辺256pxへ落として PNG8 化）。

### 抜き・切り出し
- マゼンタ(#FF00FF)背景でクロマキー。既存ツールが3つある。**新しく書く前に読むこと。**
  - `tools/assets/cut_props.py` — シートから個別に切り出す（列数指定・影落とし込み）
  - `tools/assets/key_hat.py` — マゼンタ抜き（flood fill ＋ 純マゼンタの無条件除去）
  - `tools/assets/key_room_glass.py` — 比率判定のマゼンタ抜き。**生成物のマゼンタは純粋な
    #FF00FF にならない**（実測 (254,15,253) 前後にばらつく）。固定色一致では抜けない。この教訓は
    そのまま当てはまる
- 出力先とファイル名: `assets/ui/icons/mat-<id>.png` / `prod-<id>.png` / `genre-<id>.png`
  （既存の `theme-<key>.png` `mach2..5.png` と同じ置き場・同じ命名の流儀）

## コード側の変更

絵文字は**消さずに残す**。craft.mjs の `e` は控えとして生き続ける（サムネが無い環境のフォールバック。
背景テーマで同じ判断をした前例が `game/ui/palette.mjs` の `BG_META` のコメントにある）。

1. `game/ui/parts.mjs` に `matIcon(id)` / `prodIcon(id)` / `genreIcon(id)` を足す。
   既にある `themeIcon(key)` `uic(name)` と同じ形にすること（`<img class="uic">` を返すだけ）。
2. 呼び出し側を差し替える: `craft-dialog.mjs:33` / `recipes.mjs:13,15,17` / `collection.mjs:22,39` /
   `parts.mjs:66` / 各所の `g.e`。
3. 盤面（`machine-art.mjs` 208〜222）は**最後に手を付ける**。いま色の楕円で足りているので、
   ドット絵を載せるかは実機で見てから判断する。載せるなら Phaser のテクスチャとして
   `main.mjs` の preload に追加が必要（148枚を投機的に読むと重いので、
   `hat-fit.json` と同じ「用意できているものだけ読む」方式にする）。
4. 未発見の製品はシルエット表示（`recipes.mjs` の `.sil`）。CSS の `filter` で潰しているなら
   ドット絵でもそのまま効くか確認する。

## 検収

- **16pxの原寸で読めるか。** これが唯一の合否。拡大して綺麗でも、原寸で何か分からなければ失敗。
  牛乳と砂糖、卵とバターのように、小さいと潰れて区別できなくなる組が必ず出る。
  同じジャンルのアイコンを16pxで並べて見比べること。
- ジャンル内で**色のばらつきを抑える**。食品は暖色、機械は金属、生活品は…という具合に
  ジャンルの色相をだいたい揃えると一覧で効く（`catalog.mjs` の `MAT_G_C` に既にジャンル色がある。
  それを踏襲するとよい）。
- 背景と並べて浮かないか。盤面に出す場合は特に。

## 進め方の提案

1. この指示書と `docs/stitch-prompts.md` の「2. オブジェクト」節、`make_menu_icons.mjs` の
   冒頭コメントを読む
2. 原材料の食品ジャンル（12個くらい）だけ作って16pxで並べ、タッチとサイズを決める
3. 決まったら原材料32枚を完成 → `matIcon()` を足して UI に出す → 実機確認
4. 製品はジャンル単位で刻む（食品→機械→生活品）
5. 盤面に出すかは最後に判断
